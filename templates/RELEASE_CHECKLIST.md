# Release candidate checklist

Version/tag:
Release owner:

- [ ] Public project name/license/holder approved
- [ ] Supported editor/platform versions explicitly named
- [ ] Every shipped skill has a native verification report
- [ ] Schema validation, unit tests, negative fixtures passed
- [ ] Write-enabled skills passed recovery tests including untracked files
- [ ] No tokens, private projects, licensed assets leaked
- [ ] Upstream dependency version and license list audited
- [ ] Clean-install test on documented environment
- [ ] Security report path configured
- [ ] Release notes avoid unsupported claims
- [ ] Readme quickstart tested end-to-end
- [ ] Release approved by separate reviewer
